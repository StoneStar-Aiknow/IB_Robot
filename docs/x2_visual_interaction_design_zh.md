## 一、设计决策

### 1. 产品范围与首版取舍

X2 对当前访客的可见展示行为和允许物品生成一句自然陈述，再用已有 ZipVoice 发声。
反馈动态生成；固定开场说明只用于知情告知，不作为日常短评模板。
没有值得回应的新内容时安静，并通过诊断区分正常沉默与故障。

首版限单人、工作人员在场的体验模式；不启用机械动作、ASR 问答、脸部识别或长期身份记忆。
类别只允许 `toy`（玩偶）、`sign`（手持牌）、`hat`（帽子）、`badge`（徽章），
删除通用展示物兜底。药瓶、刀具、书籍等不在首版范围，不能归入“其他物品”绕过白名单。
普通挂坠仍是后续需求，但因小目标和宗教符号风险暂不开放。

首版表达只回应类别与已确认的展示关系，不提颜色、材质、品牌、价格、牌子文字、
情绪或人物外貌等属性。这会减少表达细节，换取可验证的事实范围；措辞和语气仍动态变化。
宗教/医疗内容、身材、年龄、性别、长相及儿童外貌不作为话题。
帽子、徽章和牌子也可能含敏感内容，类别白名单只是第一层；需要内容拒绝测试和现场监督。

### 2. 访客可用的安静方式

首版选择工作人员协助，不承诺访客语音叫停，也不假设已有实体按钮。

- 开场说明：“我会留意你展示的新东西，发现有意思的内容再说话。需要安静时，请告诉旁边的工作人员。”
- 现场张贴同样的停止说明，工作人员在访客旁边值守。
- 拟提供独立的本机 `visual-interaction-console`，常驻显示状态、当前播放和停止入口。
  大按钮或 `Space` 键触发 `STOP_AND_MUTE`；`N` 为下一位访客，显式按钮才可恢复。
- console 使用受限控制接口 `/visual_interaction/control`；访客无需了解 ROS 或访问服务。
  只给操作员一条 ROS 命令而无界面，不算完成这项功能。
- 停止立即关闭新候选准入、取消合成/播放、清空待播；恢复不会自动补播旧内容。
- console 失联、操作员离岗或停止链路健康检查失败，暂停体验；实际声学静音仍须验收。

阶段二门禁包括：界面实现、人员和标识到位、操作员能真实终止发声、
失联保护有效，以及“访客提出请求→操作员触发”的演练记录。
测量分别报告人类反应耗时和系统取消耗时，不把按钮响应当作访客请求全程延迟。

### 3. 组件与进程边界

```text
相机 → 人体检测/短时关联 → 四帧人物裁剪 → VL worker
                                               ↓
                                互动会话：话题、确认、去重、有效性
                                               ↓
                             语音协调器 action → ZipVoice worker
                                               ↓
                                      可取消 PCM → 音频 runtime
```

VL、TTS 默认独立进程，各自固定 CANN 环境；统一运行时指共享契约与生命周期，
不是让它们链接进同一进程。不同 ABI 不直接证明分进程必然失败，也不保证同设备共存成功：
阶段零先验证运行库、驱动兼容与并发资源，再选共同版本、隔离进程或受控重编译路线。
音频协调器本身不加载两个 CANN 版本；禁止以修改全局 latest 解决冲突。

现有运行时支持 iterative/session/checkpoint，ZipVoice 已有该用法。
VL 首选一个完整生成请求由专用 session/executor 内部编排，KV 仅请求内存在；
请求结束/取消释放，不跨人物复用。`state_scope=request` 不能声明跨请求 stateful。
先在阶段零证明现有 API 足够表达它；若需扭曲通用抽象，提交 ADR 再决定独立 VL 服务，
保持相同配置、生命周期和诊断约定，不同时维护两套隐式调度器。

视觉会话只管理主动视觉话题；未来语音回答由 `ibrobot_agent` 接管，
视觉作为受控工具/技能提供，不新增第二套聊天循环。两者共用语音协调器。

### 4. 人物、会话与排队访客

已有 YOLOX 输出人体框，没有关键点；现有 ActorSelector 不保持身份且 actor_id 固定，
因此新增短时 IoU/中心位移/尺寸连续性关联，而不是直接把它当作 tracker。
PEAR 的参数输出也不是已经验收的低延迟二维手势服务。

- 主对象采用面积、中心距离和锁定滞回；框过旧、两人相近、交叉或关联不唯一时暂停新发声。
- actor_epoch 在关联失效或对象切换时递增，使旧窗口、VL/TTS 结果失效；不等于新访客身份。
- session_id 定义去重范围，与 actor_epoch 分开；不使用人脸 ReID 或未经验证的朝向判断。
- 同一轮四帧属于同一 actor_epoch，各帧用对应时刻的新鲜框加边距，稳定裁剪并保留手部空间。
- 保持四张 448×448 及原布局/归一化，通常无需重编 OM；检测和裁剪成本仍需测量。
  裁剪与全图黄金迁移测试分开评估。人物 ROI 中的牌子仍是不可信数据。

会话重置支持三种途径：

1. 工作人员按 `N` / “下一位访客”，在上一位交接结束后显式开始新会话。
2. 连续明确无人超过 30 秒自动重置；断流/检测超时是 unknown，不算无人。
3. 最大会话时长初值 120 秒。到期取消旧候选并暂停，提示工作人员确认是否开始新会话，
   不自动为仍站着的同一人清空覆盖记录并再次点评。

新会话先排空/隔离旧请求、清旧视觉窗口，再接受新候选；全局静音和发声预算不随之重置。
排队连续有人时依赖明确交接，不等待 30 秒空场；超时作为漏交接保护。
短时换人无法识别时仍可能保守沉默，阶段一用已知访客边界量化损失，不声称完全解决身份问题。

### 5. 封闭语义与覆盖规则

```json
{"kind":"display","category":"toy","region":"hand","reply":"你举起的玩偶真有趣。"}
```

- kind：none、uncertain、object、display；手势能力通过后再增加 action。
- category：toy、sign、hat、badge；无 fallback。region：hand、head、chest、upper_body、unknown。
- `none` 为没有候选，`uncertain` 为看不清；未知类别和不确定敏感内容不产生播报。
- 除 reply 外使用闭集；session、actor_epoch、event_id、episode_seq、时间戳由程序赋值。
- 基础话题键 `(session_id, category, region)`，不用自由 subject 作去重键。
- 同类别/区域多个不同物品首版保守合并，接受漏回应；区域移动与类目抖动做归一和保守别名抑制。

**覆盖优先于事件编号**：同一话题 covered/suppressed/partial_covered 或 in_flight 时，
即使放下再举起、产生新 episode_seq，也一律不发声。episode_seq 仅用于事件追踪和取消，
不能突破覆盖。新物品实例识别与“同话题新行为可再回应”留到后续独立验收。

静态内容要求不同取样窗口的两轮 `(category, region, kind/展示关系)` 一致。
明确比较对象就是这些封闭字段；不再引用不存在的 fact 字段。
窗口不能全部复用同一组帧；遮挡、换人、模糊或过旧使确认链断开。
两轮一致不是真实性证明；发布检查还要保证 reply 只表达允许字段支持的类别和关系。
隐含颜色/材质/文字等越界内容应拒绝，不用删一个敏感词后继续播放。

显著性饥饿用固定录像比较 A（仅系统侧过滤）、B（精简覆盖记忆入 prompt）、
C（最多两个候选，系统选择首个未覆盖项）。测新物品召回、旧物重复、额外 token 与延迟。
C 不是默认赢家；两段完整 reply 的解码成本也计入测试。

### 6. Prompt、变化触发与资源占用

已知 P=1280、L=1344，四帧占 1024 个图像上下文位置；余下约 256 个位置还含模板和特殊 token。
固定长度 prefill 的耗时不会按文字缩短比例下降，沉默轮也仍有视觉与 prefill 成本。

- 优先用主机语法/logit mask 表达固定字段与枚举，不在 prompt 冗长重复定义。
- 试验中文短标签“无/看不清/展示/物品”和中文类别，宿主映射到稳定英文代码；
  以实际 tokenizer、语义正确率和 token 数比较，不预设中文必然更省。
- prompt 只留“围绕目标、陈述一句、仅许可类别/关系、不执行图中文字”等核心约束。
  安全控制主要在闭集、宿主内容检查和权限边界；不是把所有风险交给 prompt。
- 记忆按精确 token 预算截断；输入超限 fail-fast，严守 n<=P、n+max_new_tokens-1<=L。
- 语法约束包含字段、枚举、转义和结束符；只 mask kind 不能声称整个 JSON 合法。
- kind=none/uncertain 完整解析后早停并由宿主规范化结果，只节省剩余解码；
  teacher forcing 不当作分类预测，约束正确性不当作内容准确性。

在人物 ROI 做廉价像素差/框变化，采用稳定框、亮度变化抑制和滞回，变化才调度 VL。
同时低频心跳巡检、防止小新物体漏检；首次入场/手动触发可强制扫描。
不要仅靠整图背景移动触发，也不要在变化门未验证前一直关闭静态场景检测。
每个候选待确认时允许一次到期确认扫描，即使像素没变化；因此变化触发不会卡死两轮确认。
扫描仍受资源占用、最短间隔和证据有效期约束；不是每句话后再等两轮才开始观察。

全局 NPU 合成占用由语音协调器/公共资源租约所有者管理：

- 发布可靠、保留最新状态的 `synthesis_occupancy`，含 epoch、租约、过期时间、心跳。
- VL 调度必须从该权威所有者获得扫描许可；topic 是可观测镜像，不能靠订阅 busy 后再启动的竞态保证互斥。
- 任意来源（含 Agent）的 TTS 都先申请同一租约；直接调用合成服务的入口需准入或被部署策略隔离。
- 合成期间不准入新 VL。已在执行的 VL 在 token checkpoint 退出/完成后才授予 TTS；
  当前 ACL 调用不可强杀时纳入等待预算。终止一个合成等待不意味着可立刻释放仍占 NPU 的租约。
- 占用状态过期、失联或未知时暂停新 VL，不以“没收到 busy”推断空闲。

**仅合成阶段默认与 VL 串行**。播放和冷却期间可低频观察、完成两轮确认，
但不提前发声，且候选在真正提交时重新检查对象/期限。
这一策略以阶段零 PCM 节拍与声学欠载通过为前提；CPU 争用超标则限线程、限频或暂停扫描，
相应增加延迟并重新验收，不让“默认开并发”掩盖可听卡顿。

### 7. 手势能力、动态表达与时效

首版重点为静态类别和展示关系。手势快路径须有真实关键点模型、时序识别及整机延迟验收；
YOLOX 框不够。即便识别快，若后面仍走重型 VL+TTS，不能宣称端到端快速回应。
未达标就禁用该路径，不把“最高优先”与“几乎总过期”同时写进承诺。

优先一次 VL 同时输出封闭语义与短 reply，减少双轮生成；固定候选头和回复仍须算完整成本。
首次观察的 reply 可暂存，第二轮确认后按当前关系校验；过时就丢弃，不靠反复生成凑新句子。
动态措辞不改变允许事实，全部默认示例为陈述句，不连续追问。

短动作可用与过去事件相容的语气，不说未经实时验证的“你正在……”。
有效性综合最大年龄、session/actor_epoch、对象在场、展示关系和覆盖；
“仍有人在”不能让旧事件无限有效，尚未验收的朝向检测不作为条件。

### 8. 语音协调、取消和估算完成

会话负责话题/覆盖/有效性/内容拒绝，并因失效发起取消；
协调器负责多来源互斥、优先级、预算、deadline、合成租约、播放和状态，不理解话题类别。
同话题 in_flight 直接丢弃新候选，首版不抢占旧话语；用户停止和内容失效仍允许取消。

拟新增 SpeakFeedback.action：goal 含 text、source、event_id、latest_start_at、
max_execution_duration；反馈包含阶段、预计尾音和 completion_basis。
latest_start_at 是最晚开始发声，不是播放完成期限；action 不原生提供业务 deadline。
取消接受、CANCELING、最终取消与真实静音分别记录；标准 CancelGoal 不承载自定义取消原因，
领域原因由控制接口和 event_id 关联。底层 PCM 循环、runtime 缓冲及音频焦点也需取消适配。

D 为重采样后的音频时长，t_first/t_last 为首/末 PCM 发布时间：

```text
t_end_est = max(t_first + delta_start_hi + D,
                t_last + delta_tail_hi + D_last)
t_cooldown_end = t_end_est + configured_gap
```

delta 取许可的现场校准高分位/保守余量，保留校准版本与误差；这是估算，不是硬件确认或严格上界。
超出校准条件、订阅/焦点/发送证据不足时标 UNKNOWN，不以服务 ACK 当播完。
首版正常结束只能记 covered_estimated；用户叫停记 suppressed 并全局静音；
内容失效在首 PCM 前取消保持未覆盖，可能已听见则 partial_covered，原事件不自动补播。
超时结果未知时隔离事件；晚到成功不能解除用户静音。

### 9. 时间、回放与安全入口

选定唯一首版回放模式：**实时速率、重打时间戳、所有节点 use_sim_time=false**。

- 已获许可输入按原始相对间隔 1×送出；camera/检测/裁剪证据统一映射到当前 ROS 时间。
- 原始采集时间仅作离线元数据，不参与当前年龄/deadline；不发布 /clock、不混用 sim time 节点。
- ROS deadline 在接收时换算为本机 monotonic 剩余预算，跨进程不传绝对 monotonic 值。
- 暂停、seek、loop、重启形成新 replay_epoch：暂停准入、取消旧任务、清确认窗口后重建映射。
- 系统 ROS 时钟跳变是故障并暂停准入；回放 epoch 切换是显式控制事件，不伪报时钟故障。
- 跨设备未校准时钟时，采集到声学的全程延迟不作无误差宣称。

未来需要 use_sim_time 时另设一致的测试配置与跳变策略，不与本轮验收结果混算。

拟新增 aimdk_x2_visual_interaction.yaml 和音频/观察专用 launch。
入口门禁包括节点/服务/action/厂商调用白名单、假 SDK MC/运动控制权/运动命令零调用，
以及获授权的现场观测。现有 runtime 含控制面/定时器，不以“没启动 executor”证明无副作用。
音频焦点不是运动控制权；VL 无任意硬件/ROS 调用权限。

### 10. 隐私、诊断和数据

默认内存处理，不落盘原图、录音、完整 prompt/回复或人物身份。
调试回放先取得知情同意，限定用途/访问者；原始数据默认 24 小时自动删除，
长期验收集另获许可并指定到期日，不进入 Git 或模型 bundle。
牌子文字是观察数据，不执行命令；首版不朗读。内容检查含敏感语义、属性越界、长度和字符规范化，
但不把敏感词匹配当作隐私保证；未知/高风险候选保持沉默。

`/visual_interaction/status` 区分 none、uncertain、duplicate、privacy、stale、ambiguous、
cooldown、MODEL_NOT_READY、PCM_UNDERRUN、LEASE_UNKNOWN、WAITING_NEXT_VISITOR。
诊断默认只有枚举、耗时、计数和临时 epoch，不含原图/身份/自由回复。

## 二、阶段零计划

### 11. 严格顺序与当前放行状态

阶段零只做环境核查、可复现性与基准/最小协议适配，不写完整互动业务。

| 顺序 | 工作 | 放行条件 | 当前状态 |
|---|---|---|---|
| 0A | CANN/OM/驱动兼容性审计，先只读后授权加载验证 | 每个角色的 ABI、实际库、驱动组合明确，选定进程隔离/共同 ABI 路线 | 部分只读完成，VL ABI 未确认 |
| 0B | 语音适配进入受控分支和可复现提交 | 人工审查、精确 commit、依赖/模型摘要、干净构建及测试证据齐全 | 未通过，现场仍有未提交适配 |
| 0C | 使用 0B 提交的基准测量 | 环境、输入、harness、代码均可固定复现 | 未开始 |

0A 先核对元数据，不为确认兼容就立即在现场加载模型。
纯模型兼容试验可在独立许可环境进行；使用新语音适配的音频测量必须等 0B。
ABI 不同按进程隔离分别验证实际加载库和同设备驱动；同进程不能混装不兼容 runtime。
统一 ModelRuntimeHandle 可以分别位于两个进程，接口复用与库链接策略独立。

0B 不止“保存 diff”：把重采样、消息类型、audio.play 绑定、PCM 节拍、CANN 解析、
关联配置与测试整理到可审查分支；若实际部署与该分支不同，先恢复可复现来源再测量。
构建 clean checkout、确认实际 import/可执行文件来自该 commit，记录模型与依赖摘要。
遵守 DCO/AI 披露和人工审查流程；本次没有代替贡献者提交/推送现场改动。
更改代码、OM、预处理或 ABI 后，相关基准证据失效并重测。

### 12. 基准矩阵

| 测量 | 条件与记录 | 用途 |
|---|---|---|
| VL 分段 | 预处理、视觉、固定 prefill、首 token、逐 token、none/uncertain/有效输出 | 最大输出/有效期/早停收益 |
| 实际 token | 默认模板、中文/英文标签、最小规则、A/B/C 记忆和候选逐项计数 | 明确文本和输出预算；边界 fail-fast |
| TTS | 同组约 20 字短句，单独、VL 并发、串行；含 CPU 声码器 | 合成租约策略与延迟 |
| PCM 争用 | 空闲、VL 主机解码、JPEG/人物裁剪、TTS 后处理及组合负载下播放同一许可音频 | 测发布间隔、deadline miss、欠载和声学卡顿 |
| 音频端到端 | 首 PCM 到声学首声/尾音，不同焦点/负载/句长 | delta_start/tail 校准和置信边界 |
| 取消 | 不同合成/发送/缓冲阶段，控制台/失联/内容失效 | 源停止与残余声音分开统计 |
| 检测与裁剪 | YOLOX 与 VL 同机，稳定边距、物品被截、多人、模糊/遮挡 | 人物选择与细节收益 |
| 快路径候选 | 存在真正姿态模型后测时序准确性、采样和完整发声延迟 | 手势 go/no-go |
| 原样迁移黄金 | 相同输入、模板、模型/ABI、贪心/种子；tensor/特征/logit/token | 防静默退化，变化方案另行质量对比 |
| 解码/租约/KV 小试验 | 约束语法、跨 token、取消、请求内缓存、跨来源准入竞态 | 架构适配与资源隔离 |
| 变化触发 | 亮度/框抖动、小展示物、静态持续、强制第二轮 | 调用节约与漏机会偏差 |

每条件预热后至少 30 次，交替次序报告 p50/p95/最大值、失败/超时和 CPU/NPU 负载；
30 次仅用于探索，发布 P95/停止门槛另使用更大验收样本。
PCM 测原始间隔分布与超过 chunk 周期的比例，不用平均发布率掩盖短时欠载；
若无厂商 underrun 计数，以许可声学记录的连续性判定，并明确观测范围。
有其他 NPU 用户时协调窗口，不停止或抢占其任务。

黄金测试先原样迁移；裁剪、模板、枚举、约束解码改变后不再要求与旧脚本 token 相同。
浮点容差和确定性期望事先冻结，差异定位后再评估，不事后放宽。

### 12.1 已测结论：token 预算（2026-10-21）

用 `visual_interaction.phase0.token_budget` 对板上 tokenizer 数据实测，针对当前 OM 导出
（P=1280、L=1344、4 帧 × 256 image token = 1024 个位置），**图像之后只剩 256 个位置给全部文本**：

| 场景 | prompt token | 余量 | 结论 |
|---|---|---|---|
| 最小规则（中文） | 1238 | +42 | 放得下 |
| 最小规则（英文） | 1227 | +53 | 放得下，英文标签略省 |
| 完整规则 | 1284 | −4 | **放不下** |
| 完整 A/B/C 记忆（20 条） | 1321 | −41 | **放不下** |
| 8 个候选 | 1266 | +14 | 勉强 |
| 最坏组合 | 1395 | −115 | **放不下** |

封闭 schema 自身（schema 77 + 最小规则 82 + 模板 27 = 186）就占掉 256 的大半。
解码侧不紧：最小规则下 L=1344 仍允许 107 个新 token，远超 48 字回复所需。

因此「明确文本和输出预算；边界 fail-fast」的结论是：**提示词侧是瓶颈，不是输出侧**。
阶段零必须在以下取舍中选定一条并记录理由，不能默认全都要：

1. 减帧（4→2 帧省 512 个位置，但削弱变化判断与两轮确认的证据）；
2. 减每帧 image token（256→128，需重新导出视觉 OM，影响小物件可见性）；
3. 按更大 P 重新导出语言 OM（最彻底，成本是一次完整导出与黄金重测）；
4. A/B/C 记忆移出提示词（改为宿主侧过滤已覆盖话题，模型不再被告知说过什么）。

工具对放不下的场景返回退出码 1，所以这个边界在本机就会暴露，不会留到板上某一轮才炸。
tokenizer 用 `vocab.json`/`merges.txt`/`added_tokens.json` 重建，已逐项核对与板上输出一致。

## 三、验收标准

### 14. 标注、抽样与统计判定

正式测试前冻结场景、数据划分、标注规范、阈值和分析脚本；阶段零只用于调参/可行性，
不再作为独立验收集。准确性优先于召回，但两者都报告。

“有效机会”定义：在已启用模式/类别中，主体无歧义，类别和展示关系清楚，
覆盖至少两个不同有效窗口，持续时间满足事先冻结的可观察条件，且不含禁用内容。
已覆盖同话题不计新机会；首次访客的新同类物品计机会，即使系统因漏重置而沉默。
列明曝光不足/遮挡/禁用/歧义的排除标签和数量，不能按系统输出反向挑选机会。

两名独立标注者先在调参集校准规范，验收集独立标注后由第三人裁决；
报告 Cohen kappa、原始一致率和正例一致率。候选 kappa>=0.8，未达到则先改规范并重标，
不靠只报告裁决后一致率过关。重复事件边界、物品移位和访客交接有专门标注例。

二项误差使用预先指定的单侧 95% Clopper–Pearson 上界 U，召回使用下界 L；
判定看置信界而不是点估计。零错误上界 U=1-0.05^(1/n)，约为 3/n。
同会话观测有关联，不能把大量重复帧当独立样本：
事实率每独立会话按预定随机规则抽取至多一句；重复率按每独立会话是否发生任一重复计。
存在同一人/同一天重复参与时以独立场次为簇，采用事先冻结的簇级分析或扩充独立样本，
不继续套用逐句二项 CI。所有多句结果另作描述统计。

| 指标 | 样本与口径 | 候选判定规则 |
|---|---|---|
| 发声事实错误 | 至少 400 个独立会话各抽一句；任一错误类别/关系/归属/越界属性即错误 | 单侧95%上界 U<=5%；精确允许错误数由冻结脚本算 |
| 会话重复 | 至少 500 个独立会话，每会话至少 3 个重复诱发窗口，是否发生任何话题重复 | U<=1%，不是 200 句话的点估计 |
| 禁用内容 | 至少 600 个独立策划场景，宗教/医疗/危险物/隐私牌/儿童外貌等各至少 100，可多标签 | 观察错误数必须为0且总体 U<=0.5%；各子组单报 U，不声称现实零风险 |
| 有效机会召回 | 至少 200 个独立会话各预选一个机会；另报各类别 | 单侧95%下界 L>=70%，失败与超时计漏回应 |
| 排队偏差 | 至少10场、每场20次独立访客交接，连续有人，含漏按N/超时，单独报告 | 正常交接旧记忆抑制为0；总体漏重置损失点估计<=5%，并报告场次簇区间 |
| 生命周期竞态 | 重复goal、取消/完成竞态、租约丢失/晚到结果 | 测试计划中的 in_flight 重复和静音后重播为0 |
| 静态延迟 | 至少200个合格首声，含两轮和工作负载；分位数定义提前固定 | 第二轮确认→声学首声经验P95<=5秒；另报首次机会→首声、丢弃率与CI |
| 手势能力 | 仅在启用时，至少200个独立有效动作场景 | 动作证据→真实首声经验P95<=3秒，未达标禁用 |
| 操作员停止 | 至少200次，覆盖不同播放阶段/焦点/负载 | console触发→声学静音经验P95<=1秒且最大<=2秒；访客请求→触发单独报告 |
| PCM负载 | 覆盖基准矩阵负载；冻结chunk周期与采样总时长 | 可听中断为0、发布间隔/欠载规则在正式验收前由阶段零确定并冻结 |
| 无运动与退出 | 白名单、假SDK、故障和真实只读观察 | MC/运动控制权/运动命令零调用，约定timeout内结束；124/137不算通过 |

按上述单侧精确算法交叉核算：n=400的事实错误最多12次（U约4.815%）；
n=500的会话重复最多1次（U约0.945%）；n=600零次禁用输出的U约0.498%。
这些允许次数只适用于相应固定n与独立抽样，扩样/簇分析须重新按预定方法计算。

样本数不足或独立性不成立时标“证据不足”，不是通过。
上述置信界是每指标单独95%，不声称多指标联合95%；需要联合声明时预先调整显著性水平和样本量。
排队损失报告独立指标，不能混入已覆盖机会的排除项而隐藏。
P95 行是预先约定的经验分位数门槛，另用固定方法报告区间；不把探索的30次样本当发布级保证。
策划场景的置信界只适用于事先定义的测试分布，不外推为真实展台总体风险上界。
全部门槛未获评审冻结前为提案，不能根据结果事后选择点估计/置信上界。

### 15. 发布门禁与功能降级

- 0A ABI/驱动组合未确认：不开模型组合测试，不用 latest 碰运气。
- 0B 无可复现语音提交：不做音频性能结论。
- PCM 在 VL 观察期间欠载：限频/限线程后重测；必要时暂停观察并重测延迟和召回。
- 手势延迟/准确性不达标：关闭手势能力，保留可持续展示物，不虚报最优先响应。
- 访客停止路径/人员/声学清理不达标：不上开放展台，只做静默回放。
- 语义越界或类别白名单失效：拒绝该候选/类别，不以兜底物品继续发声。

业务实现使用仓库构建流程和 colcon test；裸 pytest 仅定向排查。
文档检查与只读元数据核对不替代 ROS E2E、模型加载、声学或现场互动验收。
