# X2 固定动作路径检查的分阶段设计

状态：阶段一、二及阶段三的导出、匹配、回退和监控代码已实现，本机与 310P 隔离 Mock 验收通过。
当前 X2 没有可复用的通过记录，也没有提供运行条件证据的真实端口；配置缺省仍为双项 `online`。
隔离真机部署按操作员选择使用双项 `off`，不声明整条路径已通过验证。

基线 commit：`264e7f3b2`。适用范围为 `pose_composer.mode: fixed`、已编译种子动作和配置中的任务准备位。
生成式姿态、任意轨迹及其他机器人不自动沿用此优化。真机 pipeline 按操作员要求保持关闭。

## 1. 问题与已有证据

当前已经实现固定种子、HOME 回位及双手张开；`pose_composer.lookup.enabled` 默认开启，
查询命中时 Agent 跳过模型规划。该开关不控制下面的几何检查。

310P 离线计时条件为举臂位到 HOME、双手已张开、头部零位，未运行 ROS 节点或发送硬件命令：

| 环节 | 耗时 |
| --- | ---: |
| 候选轨迹、关节限位及速度校验 | 0.0244 秒 |
| 双手随整条机械臂路径的几何检查 | 5.0203 秒 |
| 双手首段起点误差余量检查 | 0.1290 秒 |
| 整条身体路径的凸体碰撞及静态重力检查 | 2.2909 秒 |
| 身体首段起点误差余量检查 | 0.0340 秒 |

该次总计约 7.50 秒；此前同类计时约 8.3～8.4 秒。在线状态轮询未计入这些离线数字。
机械臂轨迹本身约 10.91 秒，命令行环境初始化另测约 4.53 秒，均不属于此处的几何计算。

目前有两条重复路径：

1. `PoseComposerNode._compose_locked()` 在固定动作预览时调用 `FixedBackend.plan()`，进而执行
   `plan_safe()`，按默认张开手型及零位头部检查路径。
2. `PoseComposerNode._run_trajectory()` 在实际发送前再检查实测手型、头部和起点偏移。

另有任务准备位的张手预演：接管前、接管后重新读状态时，以及实际张手前各有检查入口。
它们的输入可能不同，不能仅凭目标名称相同就合并。

编译器已验证 HOME 与举臂目标之间的名义往返路径；现有库保存目标、模型和摘要，
没有保存覆盖实测起点、跟踪误差、手型及头部变化的可复用路径验证记录。

## 2. 配置与模式契约

当前实现的启动期配置为：

```yaml
pose_composer:
  mode: fixed
  path_validation:
    hand: online
    body: online
    # 阶段三启用 prevalidated 时提供；普通 online/off 不需要这些字段。
    # certificate_file: /path/to/fixed_path_validation.json
    # certificate_sha256: <exact file digest>
```

| 模式 | hand 的含义 | body 的含义 |
| --- | --- | --- |
| `online`，默认 | 检查实测手型随完整机械臂路径的自碰撞与净空 | 检查完整身体路径碰撞及静态重力余量 |
| `off` | 跳过手部随完整机械臂路径的计算 | 跳过身体及静态重力的完整路径计算 |
| `prevalidated`，阶段三 | 条件匹配时复用手部离线验证记录，否则在线检查 | 条件匹配时复用身体及重力离线验证记录，否则在线检查 |

两个模式独立选择。三个模式现均已实现；`prevalidated` 必须绑定有效文件，且每个请求独立匹配条件。
拒绝未知字段、拼写错误和布尔值，避免把字符串 `false` 或缺失字段误解为关闭。
YAML 中关闭值应写成 `hand: "off"` 或 `body: "off"`；未加引号的 `off` 会被 PyYAML 解析成布尔值并拒绝。
不增加环境变量、Agent 参数或单次动作请求字段来覆盖此配置。

`off` 必须在启动日志和每次任务报告中显式记录。它不等价于该路径已经验证，
会失去对应的沿途软件预测能力，也不能因为关闭而把准备位或种子标记为硬件批准。

### 各模式始终保留的检查

- Gateway 的运动授权、忙闲及当前任务归属，运行时生命周期、故障、停止状态和控制模式。
- 新网关查询、反馈新鲜度、关节名称、维度及有限值，取消和统一期限。
- 模型和动作文件摘要、配置中的准备位名称、硬件批准和空手张开批准。
- 轨迹格式、关节限位、速度限制及预算；实际下发前的起点变化检查。
- 起点和目标的单姿态身体碰撞、静态重力检查。
- 执行期间的手指、头部及命令归属监控。
- 到位稳定性、真正张手时的独立扫掠、手部跟踪和释放后确认。

第一阶段的 `off` 仍保留首段起点误差检查；关闭完整路径不自动关闭出发段检查。
第三阶段若验证记录已经包含首段误差，才可用记录的入口门禁替代这项几何计算。

当前机械臂到位容差和手指保持容差均为 0.1 rad，头部保持容差为 0.005 rad。
手指保持容差也用于手部准备、释放确认和在线碰撞包络；手部动作期间的机械臂/头部静止检查仍为 0.025 rad。
`hand=off` 的入口检查使用实测手型及机械臂起点偏差，不证明未来手指偏移包络；运行期间仍监控 0.1 rad
手指偏移。`online` 必须覆盖完整 0.1 rad 包络，旧动作库的腕部/拇指净空可能不足并被拒绝。
**到位容差不是路径安全范围**，不能把 0.1 rad 直接作为离线结果可复用的起点或跟踪误差。

## 3. 阶段一：独立开关与可观测性

目标：保持默认行为，提供精确控制范围和可核对的计时，不在本阶段宣布关闭模式与在线模式等价。

实施位置：

| 层 | 职责 |
| --- | --- |
| `robot_runtime` | 定义无几何依赖的归一化策略及策略摘要 |
| `robot_config` | 从 SSOT 读取、验证并冻结策略；参与配置快照及摘要 |
| `robot_skill_cli` / `skill_library` | 将策略身份纳入同一 delegated executor 身份，保证本地和 Gateway 目录一致 |
| `pose_composer` | 转发启动期只读参数，负责预览与执行阶段调度及反馈 |
| `aimdk_grasp` | 执行机器人专用几何检查，根据策略选择全路径或首段范围 |

配置摘要和 delegated executor 身份都应覆盖归一化策略；改变 `online/off` 后，旧计划不能继续绑定旧身份执行。
`lookup`、可写记忆及路径检查三个配置块保持独立。

执行入口先取得实测基线并完成必需状态检查，再分别选择 hand、body 的检查范围。
无论选择什么范围，都建立执行期状态监控；不能将监控的初始化放在某个可关闭检查的分支内。
`body: off` 只关闭整条路径的检查，不能连带取消 `check_pose()` 的起终点验证。
这一阶段的策略必须覆盖预览和执行前两条全路径入口，避免只跳过执行前检查、
却仍在预览中承担相同计算。离线编译器的 `plan_safe()` 始终执行严格校验，
不能继承部署中的 `off`；运行时入口和编译器入口应明确分开。

增加每次请求的阶段计时：

```text
agent_catalog / agent_lookup / agent_model / pose_preview
gateway_admission / runtime_state / ownership_prepare
hand_preflight / takeover / candidate_build
hand_path / hand_start / body_path / body_start / dispatch_gate
arm_motion / arm_settling / opening_left / opening_right / release_confirm
```

每项记录 `executed`、`skipped` 或 `reused`，耗时、策略摘要以及跳过或回退原因；
不得用“耗时为零”代替明确的跳过状态。关闭策略要通过成功结果和失败结果的报告传出，
不能只在内部异常文本中出现。

验收：

1. 默认值与显式 `online` 的接受和拒绝行为一致。
2. 单独关闭 hand 或 body，只改变对应完整路径分支；首段和必需检查仍执行。
3. 在 `off/off` 下，过期反馈、错误任务归属、关节越限、超速、取消和超时仍拒绝，且零下发。
4. 构造中段碰撞，证明 `online` 会在下发前拒绝；`off` 的报告必须明确该分支未验证。
5. 策略变化使配置和目录身份变化；CLI、Gateway 的身份计算一致。
6. 正式结论来自 `colcon test --merge-install`，补充 310P 原生构建及纯离线分项计时。

## 4. 阶段二：固定模式预览去重

目标：去掉默认手型预览中的重复全路径计算，执行前的 `online` 检查仍针对实测状态运行。

固定模式的 Compose 预览改用 `plan_for_execution()`：

- 继续检查种子/准备位身份、目标合法性、完整关节、轨迹限位、速度和相对位移约束。
- 返回目标说明、候选轨迹时长和 composition ID。
- 明确该结果是“候选轨迹”，不能以预览成功代表实测路径已通过检查。
- 执行时重新取得实测起点，规划并按阶段一策略校验；起点超出允许偏差不得下发。

生成式后端继续使用原有预览语义。名义手型的预览结果不能作为实测手型的路径验证记录。
暂不跨接管阶段缓存张手扫掠；接管及回位会改变输入，阶段三有覆盖这些变化的记录后再考虑复用。

验收：

1. 固定种子预览不调用完整路径检查；未知描述仍拒绝，且不调用姿态生成模型。
2. 预览后改变手型、头部或起点，执行仍按新实测状态检查或拒绝。
3. 预览可成功但执行路径危险的用例，在 `online` 下必须零下发。
4. 生成式预览和取消行为保持兼容。
5. 在相同姿态、同一进程预热条件下比较去重前后，分别报告预览、执行前检查和总时长。

第一、二阶段可以分成两个实现提交。每一步通过验证后再进入下一步，避免把开关问题与去重问题混在一起。

## 5. 阶段三：固定路径离线验证记录

目标：对经验证的固定路径复用结果，减少每次约 7～8 秒的完整几何计算。
板端只读取记录和做轻量门禁，不增加 MuJoCo 依赖。

### 记录内容与可信范围

第一版仅覆盖两个有向动作：HOME → arms_up、arms_up → HOME。
记录至少包含：

- 格式版本、编译器和检查算法版本、机器人模型/关节限位/动作库摘要。
- 两个端点、名义路径及时间参数、速度限制和控制频率。
- 独立 hand/body 检查参数及余量摘要，包括手指和头部允许偏差。
- 每个关节的入口偏差范围、路径跟踪误差及监控响应时间对应的误差预算。
- 允许的手型和头部范围、机器人站立下肢模型和空载假设。
- 路径净空下界、静态重力负载上界，以及覆盖这些下界/上界的验证方法。
- 记录内容摘要和来源信息；内容摘要用于一致性校验，不替代硬件批准。

现有编译器只证明名义轨迹，不足以直接生成上述误差范围的有效记录。
必须覆盖入口偏移、路径采样间隙、手指/头部变化和运动跟踪误差。
重力上界也要覆盖这些误差，不能仅凭离散采样点没有超限就声明整个范围通过。

验证范围可按保守误差管道构造：名义轨迹附近允许一定入口偏差和跟踪误差，
手指及头部也有各自范围。反馈采样间隔、状态年龄及取消响应期间可能继续移动的距离应计入预算。
尚无可靠误差上界时，不启用该路线的快速复用。

现有在线手部检查同样使用站立腿部模型。验证记录必须列明此假设；
部署不能保证该条件时不能使用记录，文件中的声明不能代替真实姿态或环境感知。

实测举臂时曾出现肩俯仰约 0.09 rad 的目标偏差；它需要被正确纳入验证或触发在线回退，
不能为了命中快速路径而直接扩大入口范围。

### 运行时门禁及回退

1. 启动时验证格式、摘要、模型和算法版本，冻结记录。
2. 非固定后端使用该模式，或显式配置的文件缺失、损坏、全局模型不匹配，拒绝启动。
3. 请求进入后先执行全部必需状态检查，再匹配有向路径、实测入口、手型和头部条件。
4. hand/body 可分别命中；各自匹配就复用，否则回退至对应的 `online` 检查并记录原因。
5. 不匹配时不自动改为 `off`，不沿用上一次的“成功”布尔值，也不靠姿态四舍五入冒充匹配。
6. 实际发送前再次确认入口条件；执行期间监控实测状态是否保持在验证范围内。
7. 运动中越出范围应请求取消并等待终态；不能在已经越界后临时补做计算再继续运行。

当前姿态到任意准备位、闭合或未知手型、转动后的头部，都不默认属于这两条路线的验证范围。
若净空不足以覆盖所需误差，保持在线检查；不自动改变目标姿态或生成绕行路径。

验收：

- 模型、文件、算法或参数变化使旧记录失效。
- 入口/手型/头部不匹配时回退在线，危险路径仍在下发前被拒绝。
- 匹配和边界内扰动使用例均符合记录范围；边界外不能误命中。
- 0.1 rad 到位容差与验证记录入口范围分别判定。
- 运动中跟踪越界、反馈过期、取消和控制归属丢失均能终止，停止未知时不提交新动作。
- 同一组样本比较在线与复用结果；对离线方法本身做几何和重力边界验证。
- 310P 分别记录匹配、回退、冷启动和预热的耗时，确认无 MuJoCo 导入。

性能目标是匹配时将整条路径重复计算压到 1 秒以内的门禁和必要小范围检查；这不是当前实测结果。
不把命令行启动、模型调用、机械臂约 11 秒运动和释放后观察时间计入这项性能承诺。

## 6. 交付与回退顺序

| 阶段 | 可交付结果 | 回退方式 |
| --- | --- | --- |
| 一 | 默认在线的独立开关、冻结策略身份、完整分项计时及报告 | 两项配置均为 `online` |
| 二 | 固定候选预览去重，执行前统一检查 | 恢复固定模式原有预览路径检查 |
| 三 A | 离线记录格式、编译器和边界验证，默认不启用复用 | 不配置复用文件，保持在线 |
| 三 B | 实测条件门禁、独立命中/回退及执行期范围监控 | 将 `prevalidated` 改回 `online` |

各阶段先做本地和板端隔离 Mock、构建、计时，再安排对应的真机验收。
本设计不自动启动 pipeline、不自动重试历史失败任务，也不修改当前配置以关闭检查。

依赖声明或 setup/build 变化若触发仓库双平台 Docker 门禁，在正式 PR 检视前按仓库流程补齐验证；
当前 checkpoint 为本地提交，未创建或推送 PR。

## 7. 实现与验收记录（2026-11-04）

本节保留路径开关最初实现阶段的记录，当时手指保持容差为 0.025 rad；后续状态见第 8 节。

- 策略由 `robot_runtime.path_validation` 统一归一化，配置加载器解析相对文件路径并冻结 SHA256。
  配置摘要和 CLI/Gateway delegated executor 身份覆盖策略，启动参数只读，无单次请求覆盖入口。
- `aimdk_grasp.path_validation.ValidationGate` 是固定轨迹的实测门禁。
  hand/body 完整路径独立选择；所有模式保留状态和归属、限位/速度、实测头部的起终点身体/重力、
  首段误差和下发前起点漂移检查。独立张手扫掠未合并或关闭。
- 固定 `plan()` 仅构造候选；离线 `plan_safe()` 始终检查完整名义路径。
  生成式后端未使用新开关。Mock 验证预览成功后，在线执行仍能拒绝中段碰撞。
- Agent 事件 `planning_timing`、Gateway 的 `gateway_admission` 审计、动作结果 `preparation` /
  `path_validation` 分别记录各层时间。状态明确区分 executed、skipped、reused、failed，
  未到达的阶段和已在目标的跳过有明确原因。报告包含冻结的策略身份，不跨请求复用检查结果。
- `pose_compile_validation` 对两条有向直线路径导出验证记录；手部覆盖入口、跟踪、采样、
  手指/头部及响应预算，身体增加全局连杆长度推导的静态重力误差上界。
  不支持的关节轴心结构或未通过的分量写入拒绝原因，不生成该分量的通过证明。
- 运行时核验模型、动作库、算法源码及参数绑定；分量缺失、入口/手型/头部不匹配或缺少实时条件证据，
  分别回退在线。文件损坏或全局绑定不匹配则拒绝启动。
- `LiveConditions` 要求同一运行期间的新鲜站立/空载证据及已验证的速度、取消响应上界。
  当前 `RuntimeRestorePorts` 没有此类生产者，不通过配置常量伪造条件，因此不会在真机启用快速复用。
  反馈年龄沿用 transport 在 ROS 时钟域计算的 `feedback_age_s`，不与 monotonic 时钟混算。
- 范围监控失效会取消并等待终态；取消或接收响应不明确时报告 `POSE_STOP_UNKNOWN`。
  姿态节点拒绝后续动作，Gateway 保留准入；迟到的未知结果同样不释放准入。

实际 X2 库的导出试验使用入口 0.02 rad、跟踪 0.025 rad、反馈年龄 0.1 s、轮询 0.2 s、
