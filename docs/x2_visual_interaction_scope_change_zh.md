# X2 主动视觉互动：首版范围变更（动作 + 展示物 + 克制穿戴物）

- 状态：范围决定已定，契约与代码改动待实施。
- 日期：2026-10-21。
- 依据实验：板上 InternVL 256 token/帧，真实历史画面 12 轮 × 3 配置（见下「实验证据」）。
- 上游文档：[`x2_visual_interaction_design_zh.md`](x2_visual_interaction_design_zh.md)。

## 1. 变更摘要

原首版是**物品驱动**：识别到白名单物品（toy/sign/hat/badge）才说话，否则安静。
新范围改为**以人为主、物品捎带**：

| 说什么 | 首版是否允许 | 备注 |
|---|---|---|
| 动作、姿态、手势 | **新增允许** | 原契约把 `action` 显式排除 |
| 手持展示物 | 允许（原有） | 大件为主 |
| 穿戴物（帽子等） | 允许，**只陈述不评价** | 见 §4 |
| 整个人的审美评价 | **默认关闭** | 不随配置开启 |
| 小饰品（徽章、胸针） | **移出首版** | 256 token/帧 下不可靠 |

## 2. 实验证据：为什么这么改

### 2.1 模型不理解跨帧动态（12 轮 × 2 配置 = 24 次，全部"没有变化"）

同一组真实画面，问"对比这几帧，动作发生了什么变化"：

```
[0011] 4帧问变化: 这个人的动作或姿态没有变化…双手举起，似乎在做手势或准备说话
[0011] 4帧问状态: 这个人正在用手遮住眼睛                    ← 同一组画面
[0008] 2帧问变化: …双手举起，做出两个竖起大拇指的手势        ← 错
[0008] 4帧问状态: 这个人正在做手势，比出和平手势            ← 对
```

**结论**：要求时序对比时，模型不仅答不出变化，还会丢失单帧本可看对的信息。
因此首版**不承诺任何跨帧动态理解**，`kind` 描述的是**当前瞬时状态**，不是变化过程。
窗口的多帧只用于"选一帧较清晰的"和证据时效，不用于动态推理。

### 2.2 4 帧相对 2 帧没有质量优势，但贵 526 token

| | 4 帧 | 2 帧 |
|---|---|---|
| 答"没变化"比例 | 12/12 | 12/12 |
| 动作描述准确度 | 相当（第 6 轮反而更差） | 相当 |
| 图像占位 | 1024 | **512** |
| 最小规则 prompt | 1238（余 42） | **712（余 568）** |
| 最坏组合 prompt | 1395（**超 115**） | **869（余 411）** |

**结论**：首版改用 **2 帧**。预算问题随之消失——7 个场景全部放得下，
最坏情况仍余 411。**不需要重新导出视觉 OM**（原备选方案「256→128 token/帧」不再必要，
也就不承担小物件可见性进一步下降的风险）。

### 2.3 动作描述在 256 token/帧 下可用

12 轮静态问法的输出：比 V 字、挥手、遮眼、捂脸、指镜头全部分辨正确，
并能看出"面带微笑"。连续 4 轮退化为"似乎在调整或检查设备"时，
模型自身用"似乎/可能"表达了不确定——这正好可映射到 `uncertain`。

## 3. 契约改动

### 3.1 `kind` 新增 `action`

```
KIND_ACTION = "action"
KINDS = (none, uncertain, action, object, display)
SPEAKABLE_KINDS = (action, object, display)
```

原契约注释称「`action` 需要真实关键点模型和实测端到端延迟」。
**该理由不再成立**（§2.3 证明 VL 单帧即可描述手势），但**保留另一半约束**：
首版不声称动作的时序准确性，不做快路径，不承诺手势触发的实时性。

### 3.2 动作类别（新增封闭集）

纯动作没有物品类别，而去重需要一个键。按动作类别分桶：

```
ACTION_GESTURE     = "gesture"       手势：比 V、挥手、指向、竖拇指
ACTION_HOLDING     = "holding"       手里拿着/举着东西（物品本身看不清）
ACTION_INTERACTING = "interacting"   在整理、操作、检查某物
ACTION_CATEGORIES  = (gesture, holding, interacting)
```

**无 fallback 成员**，与 `CATEGORIES` 同理：留一个"其他动作"等于把判断交回模型。
不在这三类里的动作 → `kind: none`。

### 3.3 `CATEGORIES` 去掉 `badge`

```
CATEGORIES = ("toy", "sign", "hat")      # badge 移出
```

徽章在 448×448、256 token/帧 下占几十像素，不可靠。`sign` 保留——
"举着一个牌子"这件事可见，但**读牌子上的字仍然禁止**（原规则不变）。

### 3.4 `TopicKey` 容纳两种主体

现为 `(category, region)`。改为同时容纳物品与动作：

```python
TopicKey(subject_kind, subject, region)
#   物品: ("item",   "hat",     "head")
#   动作: ("action", "gesture", "upper_body")
```

同一动作类别一会话只说一次：比完 V 再挥手不再说（同属 `gesture`），
符合"保守、不唠叨"。覆盖优先于 `episode_seq` 的既有规则不变。

## 4. 待决：穿戴物"只陈述不评价"与现有白名单冲突

**这是实施前必须先解决的一处矛盾，不能在改代码时顺手定。**

你定的边界是「只陈述，不评价」。对 `category=hat` 实测现有实现：

| 期望 | 实测结果 |
|---|---|
| ✅ `你戴的帽子我看到了。` | 通过 |
| ✅ `你戴的帽子很有特点。` | 通过 |
| ✅ `你的红帽子很显眼。` | **被拒** — "红"和"显眼"都不在允许词表 |
| ❌ `你的帽子很好看。` | **通过** — "好看"在允许词表，`person` 模式只挡"你真好看" |

也就是说现有边界**恰好反了**：陈述性的颜色被拒，评价性的"好看"被放行。
（注：颜色同时还有 `_OUT_OF_RANGE` 的 `colour` 模式，但词表那一关先触发。
放开颜色需要两处都改，只改一处无效。）

两处要改，建议方案：

1. **颜色**：对 `hat` 等穿戴物与展示物放开基本颜色词（红/黄/蓝/黑/白…）。
   理由：颜色是画面直接可见的事实，属"陈述"；原先拒绝它是为防"材质/品牌"类
   不可验证推断，颜色不在其中。
2. **评价词**：把"好看/漂亮/帅/可爱"从允许词表移出，无论指向人还是物品。
   保留"显眼/有特点/醒目/看到了"这类陈述性措辞。

**风险**：方案 2 与 `badge` 移出会影响 **4 个测试文件共约 20 处引用**
（`test_semantics.py`、`test_topics.py`、`test_launch_builder.py`、
`test_visual_interaction_contract.py`）。其中如
`test_an_ordinary_remark_still_passes` 把"你别着的徽章真好看""你的徽章很漂亮"
当作应当通过——那些用例写的是旧边界，需要随契约一起改，
**不是把断言放宽，而是换成新边界下的句子**。

## 6. 本次不变的部分

- **不发声**。仍只发 `VisualInteractionUtterance` 到 topic，等发声协调器。
- **不接真 VL**。`vl.implementation` 仍只接受 `fake`。
- 无运动门禁、两轮确认、会话边界、覆盖规则、`set_enabled` 静音：全部不变。
- 禁止读画面文字、禁止推断情绪/年龄/身份/信仰：全部不变。
