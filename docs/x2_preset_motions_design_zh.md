## 1. 已确认需求

- 系统订阅现有人体姿态估计器 PEAR 的输出。
- 系统用规则识别头顶比心。
- 识别条件偏宽松，容纳参考图的差异。
- 人保持比心时，机器人保持标准姿势。
- 人退出比心后，机器人平滑恢复普通镜像。
- 模板控制双臂和双灵巧手。
- 模板不控制腰部和腿部。
- 双手之间保留间隙。
- 头部避让约束覆盖进入、保持和退出。
- 头部间距先采用 20 cm 的仿真设计目标。
- 间距从完整几何的外表面计算。
- 检查范围包含手指、手掌、手腕和前臂。
- 如果目标不可达，保留结果供用户审查。
- 系统禁止自行缩小头部间距。
- `mirror_stop` 和长捂优先于模板动作。
- 人主动摸头时，系统结束本轮镜像。
- 系统保留后续增加动作规则的接口。

20 cm 是设计目标，不是实机安全认证。
三张参考图不构成 PEAR 阈值验证数据。

## 4. 识别模块

模块只读取现有输出。
模块不修改人体重定向。
模块不启动新模型或相机。

输入包括以下 3 个话题：

- `/motion_imitation_stream/pear_frame`
- `/motion_imitation_stream/actor_state`
- `/mirror_session/state`

`PearFrame` 发布 SMPL-X 旋转参数。
匹配器复用人体正向运动学重建关节位置。
正向运动学的英文简称为 FK。
模块不借用机器人重定向结果识别人。

规则使用人体坐标系和肩宽归一化。
候选特征包含双肘高度、外展和屈肘程度。
候选特征还包含双手高度、间距和向内收拢程度。
规则允许参考图中的身体侧倾。
规则不强求准确的手指心形。

负样本验证覆盖普通举手、伸懒腰和摸头。
部分双手摸头姿势与比心存在几何重叠。
首版必须报告这种误触边界。

初始持续确认时间拟为 0.5 s。
初始退出确认时间拟为 0.4 s。
进入阈值和退出阈值分别配置。
最终阈值以 PEAR 回放验证结果为准。

模块拒绝过期、非有限值和乱序数据。
模块只处理当前选定演员的数据。
演员丢失时，模块沿用镜像的丢失处理。
输入失效时，系统禁止无限保持比心。

规则、匹配状态和机器人模板分别存储。
首版只注册 `overhead_heart`。

## 5. 动作接管与恢复

动作过程包含进入、保持和退出。
保持条件来自匹配状态。
系统禁止用超长录制代替保持状态。
系统禁止循环提交一次性技能代替持续持有。

模板使用具名动作控制权。
模板禁止冒充普通镜像流。
交接期间只能有一个手臂和手部命令源。
普通手势覆盖不能修改模板的手指目标。
姿态推理在模板保持期间继续运行。

进入从当前实测姿势开始。
退出对接当前镜像目标。
过渡遵守现有位置、速度和加速度限制。
系统验证每条过渡路径。
系统不能把目标姿势安全视为整条路径安全。

停止信号优先于保持和自动恢复。
停止后，旧匹配结果不能重新启动动作。
停止、故障和失联不触发自动重启。
长捂在动作交接和保持期间必须有效。
人主动摸头时，系统沿用当前结束本轮的规则。

当前一次性具名动作接口没有保持参数。
控制权 subagent 核查最小接口扩展方案。
实现必须保留 Gateway 准入和安全检查。
接口方案通过主 agent 审查后才能实现。

## 6. 仿真模板与头部避让

仿真使用 X2 模型和完整双灵巧手几何。
仿真核查手指关节顺序和拇指安装差异。
仿真检查双手间距和手与身体的间距。
头部检查覆盖允许的头部姿态包络。
仿真不能默认其他功能始终固定机器人头部。

模板优先选择头顶外侧的大心形。
模板不要求双手接触。
路径不能穿过头部或头部感知器附近。
验证包含正面、侧面和进入退出动画。
截图和数值报告同时保存。

现有镜像控制障碍函数简称为 CBF。
具名动作不自动经过镜像 CBF 过滤。
系统禁止把具名动作视为免检白名单。
现有精确目标验证接口不等同于完整实机认证。
模板必须另行验证完整手部几何和路径。

如果路径不满足间距，系统拒绝该次进入。
如果退出路径不满足间距，系统报告退出受阻。
系统保留最近的有效目标和停止能力。
系统禁止硬切到未验证目标。

## 8. 匹配事件

事件话题：`/preset_motions/matched`。
消息类型：`std_msgs/msg/String`。
内容格式：JSON。
事件可靠传输，不持久重放旧事件。

字段定义如下：

- `schema_version`：固定为 1。
- `event_id`：每次确认匹配的唯一编号。
- `template_name`：首版为 `overhead_heart`。
- `score`：0 至 1 的规则分数。
- `source_stamp`：源图像时间，含 `sec` 和 `nanosec`。
- `matched_stamp`：确认时间，含 `sec` 和 `nanosec`。
- `actor_id`：当前演员编号。

规则分数不是经过标定的概率。
一次持续保持只发一次确认事件。
退出并再次确认时，系统生成新事件。
匹配事件不证明机器人已执行成功。
动作执行结果通过独立状态报告。
主 agent 把契约交给拍照特性对齐。
